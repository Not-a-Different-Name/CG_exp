## 2026-11-14 · W1 机器人核心

### W1-0 底座验证与版本基线

- 先运行参考工程自带 `viewer.exe` 无头截图（`--shot`），确认本机 GLSL/阴影可用

- `git init` 建立基线提交，此后每任务一提交，可回退可追溯

### W1-1 机器人层级建模

- AI 的做法：新增 `src/robot.h/.cpp`（约 300 行）。9 个长方体部件（躯干/头/双眼/
  天线/双臂/双腿），每个部件是场景中的一个 Object，每帧由「根·局部关节链」的
  4×4 矩阵乘积拆出 pos/xform 写回 —— 这样经典管线、GLSL 着色、阴影 pass 三条
  路径自动一致（渲染器按 T(pos)·xform·S(size) 组合模型矩阵）
- 关键知识落地：齐次坐标统一平移/旋转/缩放；矩阵从右往左乘（先自转再公转）；
  四肢 T(关节)·R(关节角)·T(杆件偏移) 三明治结构使旋转支点在肩/胯
- 遇到的问题：最初把机器人设计成单个自绘 Object，内部用 glPushMatrix 变换部件；
  审查渲染器代码发现 GLSL 路径的阴影投影用的是**每个 Object 一次**的 u.model
  uniform，单 Object 多部件会让 9 个盒子投影到同一位置 → 改为每部件一个 Object
- 验证：4 姿势 + 线框 + 正交前视图 + 经典管线共 7 张截图，视觉模型逐张确认
  （部件齐全、贴地、T-pose 对称、挥手绕肩）

### W1-2 行走关节动画

- 1.6Hz 正弦关节曲线：双腿相位相反（评分点"两条腿交换向前"）、双臂与同侧腿
  反相摆动、重心每周期两次起伏；姿势切换用指数平滑插值防跳变
- 问题：本机没有 ffmpeg，无法直接录视频取证 → 增加 `--time`/`--robot-walk`
  出图钩子，按 0/¼/½/¾ 相位渲染 4 张定格，构成可复核的"逐帧"证据
- 验证：¼ 相位与 ¾ 相位腿部/臂部完全互换（视觉模型确认），符合正弦预期

### W1-3 交互接入 + 自检

- 数字键已被视图/投影占满 → 姿势用 `n`、行走用 `b`；中键菜单加 Robot 子菜单；
  帮助屏与 HUD 同步更新；Tab 选中 "Robot" 根物体后 t/r/y 即整体变换
- 交互没法截图验证 → 沿用工程自带 `--selftest` 模式补 4 条几何不变量断言：
  T-pose 臂中心=肩高、站立臂下垂=肩高-半臂长、站立脚底 y=0、行走定格腿中心
  下降量=0.54×(1−cos30°)
- 遇到的问题：第 4 条断言首跑失败——期望值漏算了该姿势 0.03 的重心下沉，
  属测试自身笔误而非实现错误，修正后 15/15 全过

## 2026-11-14 · W2 森林生态

- 森林从三种固定树型改为 L-system：字符串重写（F→展开式，迭代 3 代）+ 3D 海龟
  解释（前进/偏航/俯仰/翻滚/入栈出栈）生成锥台枝干，末端挂叶团（针叶小锥/
  阔叶椭球）；草簇与花朵程序化散布

  调整即重建整片森林（复用 Forest 物体的 Mesh，adopt 换数据）
- 遇到的问题 ①：把形状函数声明挪进 forest.h 时忘了同时移出匿名命名空间，
  产生重载歧义（编译报 C2668），同时误删了 scene.cpp 的命名空间闭合括号

- 遇到的问题 ②：L-system 展开是指数增长，粗选文法时单树可达 4096 段枝，
  150 棵树会到百万三角形级——改为每树 40~70 段的文法（全场景约 29 万三角形），
  并把深度+1 档位留给演示"分形复杂度指数增长"
- 验证：selftest 增加两条断言（同种子几何全等、+1 迭代单调增长）；
  截图经视觉复核：针叶分层/阔叶叶团/灌木可辨、贴地、空地干净

## 2026-11-14 · W3 加分项（第 1–2 项）

### W3-1 三次贝塞尔闭曲线漫步

- 新增 `src/bezier.{h,cpp}`：给定 N 个锚点生成 N 段三次贝塞尔闭曲线，
  控制点用 Catmull-Rom 公式自动求（`C1 = P1 + (P2−P0)/6`，`C2 = P2 − (P3−P1)/6`），
  接缝处切向连续，不用手调手柄
- 求值用 de Casteljau（数值稳定，避免展开多项式的抵消误差）；
  每段均匀采样 24 点并累加**弧长表**，`evalAtDistance(s)` 二分查表 + 线性插值，
  `tangentAtDistance(s)` 取相邻采样点方向——机器人按 `s = 1.05·t` 前进，
  速度天然恒定
- 机器人新增 `onPath` 状态：`P` 开关；`B` 显示曲线网格（沿曲线每 2 个采样点
  放一段细圆柱，锚点金色椭球、手柄蓝灰小椭球），该网格 `selectable=false`，
  Tab 不会选中它
- 遇到的问题 ①：**按参数 u 均匀走 ≠ 匀速**。贝塞尔参数 u 与弧长不是线性关系，
  长段/短段速度差肉眼可见。改用弧长参数化后，自检以 0.15 为步长测位移，
  断言 \|step−0.15\|<0.005 通过
- 遇到的问题 ②：路径与兔子撞位。曲线右侧锚点正好穿过兔子站位 (2.6,−1.6)，
  机器人会从兔子身体里穿过。把兔子后移到 (3.3,−2.6)、整条路径居中到 (0,0.4)，
  并在种树避让列表里加入路径采样点
- 遇到的问题 ③：帮助界面溢出。原有 56 行单栏已经贴到 800px 窗口底部，
  再加 P/B/G 三行会被裁掉——改为左右两栏（自动测量最长行宽）
- 遇到的问题 ④：`--time` 只锁机器人，动物仍走真实时钟，追拍 t=3 与 t=6
  得到同一姿势。新增 `robotTimeOverride()` 共享时间轴，且 `--time` 在
  headless 单帧出图时同样生效
- 证据：`W3-1_path_default.png`（默认机位）、`W3-1_path_guide.png`（B 键
  曲线可视化）、`W3-1_path_quarters.png`（t=0/2.82/5.63/8.45 四相位拼图）

### W3-2 动物贝塞尔漫游 + 追赶戏码

- 鹿、狐狸的圆形路线升级成 6 锚点贝塞尔闭环（与 W3-1 同一套 `BezierPath`），
  锚点手摆成不规则环，更像动物踩出来的小径；速度仍由弧长参数化保证恒定
- 行为：走 11 秒 / 吃草 4 秒（狐狸整体错开 4 秒）；吃草时位置冻结、身体俯倾；
  机器人进入鹿 1.35 单位内时鹿「警觉」抬头、不吃草
- `G` 追赶演示：鹿切到逃跑状态（fleeSpeed 1.6，不再休息吃草），机器人目标点
  取 `鹿位置 − 前进方向 × 1.25`，Yaw 与鹿的前进方向一致；狐狸不受影响
- 遇到的问题（关键）：**朝向公式用错坐标系**。动物模型面朝 +X，Yaw 是
  `atan2(-hz, hx)`；机器人模型面朝 +Z，`Ry(θ)` 把 +Z 转到 `(sinθ, cosθ)`，
  所以必须是 `atan2(hx, hz)`。直接复用动物公式会让机器人「倒着追」
  （朝向与逃跑方向点积 = −1）。修复后补了一条回归断言：用前后两帧鹿的位置差
  求实际运动方向，再与机器人前向做点积，要求 ≈ +1（实测 0.999）
- 遇到的问题（次要）：修复后仅凭截图难以确认朝向——侧后方机位下机器人没有
  明显正反面特征，眼睛不可见时容易误判。改为打印数值（鹿 (-2.74,1.66)，
  方向 (-0.60,0.80)，机器人 (-1.99,0.76)，Yaw −39.7°，dot=0.999）后确认
- 布局：鹿环中心 (−3.7,0.7)、狐狸环中心 (−5.2,−2.8)，与机器人路径、兔子、
  默认机位均不重叠；`scene.cpp` 种树避让圆同步更新
- 证据：`W3-2_loops_2up.png`（t=3 / t=9 两只动物在各自环上的不同位置，
  HUD 状态从「walking」变「grazing」）、`W3-2_chase_2up.png`
  （t=3 机器人从鹿后方接近；t=6 鹿已跑远、机器人仍保持在其正后方）
- 验证：MSBuild Release x64 零警告；`--selftest` 30/30 全过

## 2026-11-21 · 森林巡游打磨与角色导入（W3-3）

本轮由另一会话完成并推送（`a28d7c7`）。此前只写进了 README 与实施计划，过程日志漏记，这里按代码实际实现补记。

**巡游打磨**

- 实时进入森林（非批量出图）时默认开启路径巡游；批量截图仍只按显式参数执行，避免静默改变历史证据。
- 新增 `Shift+P` 暂停/继续巡游、`Shift+B` 显示路线、`Shift+G` 开关追赶；帮助页改为 3 个页签（1 探索 / 2 巡游 / 3 视图），鼠标点页签或按 `1`/`2`/`3` 切换。
- 手动 `n`/`b` 先关闭追赶，`P` 先清追赶位姿再切路径——自动运动与手动操作不再抢控制权。

**角色导入**

- `i` / `Shift+I` 调 Windows 文件对话框（`GetOpenFileNameW`）选 PNG 或 OBJ；`k` 在「内置机器人 → 最近 PNG → 最近 OBJ」间循环，`M` 按实验规范 W3-3 在「拼装机器人 ↔ 导入模型」间二态切换；右上角显示来源文件名；命令行 `--character <路径>` 与 `--slim-skin` 供无头出图。导入日志打印面数、法线、上轴与缩放。
- **PNG 皮肤**：固定 64×64，按 Classic（手臂 4px）/ Slim（3px）六部件展开图生成六个带 UV 的盒体网格（头/躯干/双臂/双腿）。每面按标准 net 取块；overlay 层按 alpha 合成到底层；底层完全透明处用中性灰 166 兜底避免黑边；纹理用 NEAREST 过滤保留像素画锐利。导入后仍使用原机器人的关节链，挥手、走路和巡游动画照常播放。
- **OBJ 模型**：约定 Y 上、+Z 前，按包围盒高度缩放到 2.35 单位并对齐地面，作为根节点下的独立 Object，可随巡游转向并做整体变换；像素贴图保留最近邻采样（`preserveSmallTexturePixels`）。
- 实现要点：UV 的 v 轴方向必须处理——位图首行在顶部，而纹理坐标原点在左下，所以采样时反转每位图的纵向顺序，并让第 0 行上传到 v=0，否则皮肤上下颠倒。切换形态时遍历场景释放上一份导入网格并置空，避免泄漏与重复上传。
- 样例 `Models/TrailSurveyor/`（444 行 OBJ + 自绘 64×64 像素纹理）为原创方块造型，不使用 Minecraft 官方素材或皮肤。
- 限制：带骨骼的格式与部件级 OBJ 绑定未实现（导入 OBJ 只能整体变换）；旧版 64×32 皮肤不支持。
- 证据：`report-assets/review/render/character-import.png`。

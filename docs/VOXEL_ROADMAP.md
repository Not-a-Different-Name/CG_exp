# 从图形学实验到体素森林沙盒

日期：2026-11-20。定位：个人学习与原创小作品路线，不替代尚待核实的课程任务要求。

## 目标

做一块能够探索、拆放方块并保存的小型森林世界。玩家能搭台阶、挖通道、修一座林间小屋，退出后重新进入，建造仍然存在。第一个正式版本完成这一条体验，再加入机器人和动物。

本方案根据当前 C++17、freeglut、GLSL、VBO/EBO、相机和程序化森林基础制定。它是建议路线，本轮没有实现体素系统或安装新依赖。

## 技术认识

OpenGL 负责把准备好的几何与材质绘制到屏幕上。世界如何存储、哪些表面需要绘制、玩家怎样碰撞、方块怎样修改和保存，需要应用程序自己实现。

Minecraft Java Edition 长期使用 OpenGL。Mojang 在 2026-02-18 发布的官方说明中宣布准备向 Vulkan 迁移，因此不能把“所有版本的 Minecraft 始终都用 OpenGL”作为前提。当前学习阶段继续使用 OpenGL 有利于利用已有基础，世界数据和游戏逻辑也可在将来更换渲染后端时保留。

来源：[Mojang 的渲染技术说明](https://www.minecraft.net/en-us/article/another-step-towards-vibrant-visuals-for-java-edition)。这里没有据此推断 2026-11-20 所有发行版本的具体迁移进度。

## 第一版的范围

- 一个有边界的 64×32×64 世界，采用明确的世界坐标约定。
- 空气、草地、泥土、石头、木头、树叶；第一版树叶按不透明方块处理。
- 第一人称观察和行走、重力、跳跃、与实体方块碰撞。
- 准星选中近处方块，拆除、放置和简单材质切换；禁止放置方块把玩家身体封住。
- 固定种子生成起伏地形与少量树木。
- 单个存档，保存并恢复实际修改；保存世界尺寸、版本和种子。
- 简洁提示、暂停和返回菜单、统一配色及一处经过设计的出生点。

验收体验：启动 → 走到空地 → 搭台阶 → 爬上台阶 → 挖开一个方块 → 保存退出 → 重启恢复相同世界。

## 推进顺序

按成果推进，不提前承诺日程。每一步都应能独立运行、录制并由用户解释。

| 阶段 | 可见成果 | 核心知识 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1 方块试验场 | 一个 16×16×16 的测试区域，能从不同方向观察 | 三维数组、BlockId、索引与世界坐标、网格生成 | 用户能解释一次方块读取如何转成顶点数据；内部相邻表面不生成 |
| 2 世界可编辑 | 准星选择、拆除和放置方块，画面立即更新 | 射线与网格遍历、命中面法线、编辑距离 | 相邻面选中正确；不误选背后方块；边界坐标与无命中不崩溃 |
| 3 角色可行走 | 有重力、跳跃和碰撞，可搭台阶后站上去 | 时间步长、速度、轴对齐包围盒和附近方块查询 | 不穿地、不穿墙；角落和头顶碰撞可用；暂停恢复不突然大步移动 |
| 4 区块世界 | 扩大到 64×32×64，局部编辑只更新受影响网格 | 16³ 区块、脏标记、世界与区块坐标换算 | 改区块边界时相邻区块正确重建；不因每帧重建世界而卡顿 |
| 5 生成与保存 | 固定种子生成地形，退出重开保留建造 | 确定性生成、序列化、文件版本和失败处理 | 同种子一致；存档损坏给出明确结果；写入失败不覆盖掉唯一有效存档 |
| 6 作品打磨 | 一处完整林间营地，清楚的操作反馈和统一视觉 | 构图、材质、光照、界面、音效和体验验收 | 新用户能自行完成建造与保存流程，演示过程中没有遮挡和状态混乱 |

如阶段 2 更能维持兴趣，可以先做编辑，再补角色物理。阶段 4 的性能优化应根据测量逐项进行。

## 架构约束

保留课程 `viewer`，未来新增独立 `voxel_demo` 目标或场景入口。本轮工作区已有多项未提交的修复，实施前先保存清晰的版本基线，避免扩展覆盖课程成果。

第一轮继续用现有 C++17、freeglut、GLSL 和网格基础，不同时切换语言、窗口库和图形 API。后续若需要更完整的窗口与输入控制，可在独立目标中评估 GLFW；GLFW 负责窗口、上下文和输入，仍需自行实现世界与玩法。参考：[GLFW 官方入门](https://www.glfw.org/docs/latest/quick_guide.html)。

建议职责：

```text
World / Chunk       存 BlockId，查询和修改世界
ChunkMesher         根据方块与相邻数据生成可见表面
Renderer            上传网格、管理材质和绘制
PlayerController    输入、速度、重力和碰撞
BlockInteraction    准星射线、选中、拆放规则
WorldGenerator      根据种子生成基础世界
WorldSave           存档格式、读取与安全写入
```

关键要求：方块是数据，不要把每个方块变成当前 Scene 中的一个 Object。每个区块合并生成网格，只为实体与空气接壤的面生成几何。修改一个方块时标记所在区块；若位于边界，也标记相关邻居。背面剔除与不生成内部面是不同层面的工作。

CPU 先完成这些数据与网格生成，GPU 接收可绘制的顶点／索引。第一版不需要计算着色器、后台线程或复杂实体框架。

## 学习方式

每次围绕一个结果，只补足当前需要的知识，不先通读大量引擎课程。

1. 先画出数据流和一个小例子，例如“挖掉这块石头后，哪几个区块、哪些面需要更新”。
2. 自己实现一小部分核心逻辑：数组索引、暴露面判断、放置位置或碰撞查询。
3. 用截图、日志和几个边界用例检查结果，记录自己能解释与尚不能解释的部分。
4. AI 可负责接口草稿、重复代码、错误定位和反例，关键算法需要用户用自己的话讲明白并能做小改动。

建议最先独立掌握：C++ 的数组／vector、结构体／枚举、引用与生命周期；三维向量、点积／叉积、坐标变换；顶点缓冲与着色器输入。更复杂 C++ 技巧暂不作为开工前置条件。

## 后续扩展顺序

| 顺序 | 扩展 | 前置条件 |
| --- | --- | --- |
| A | 原创森林与建造风格、简洁音效和清楚的交互反馈 | 第一版建造与存档流程完成 |
| B | 机器人沿玩家修建的小径巡护，动物在保留的空地活动 | 体素世界能提供地面高度和实体查询；方块修改后能修正路径有效性 |
| C | 曲线编辑路径与建造结合 | 路径与碰撞世界一致，能提示被方块堵住的路线 |
| D | 世界更大、视锥剔除、合并相邻共面表面（greedy meshing） | 已记录网格生成时间、三角形数、绘制调用和帧耗时，确有对应瓶颈 |
| E | 昼夜、体素环境遮蔽、基础方块光照 | 能分别说明美术价值与性能成本，有稳定静态画面基线 |
| F | 洞穴、水和透明材质、区块流式加载 | 已处理相邻数据、编辑、存档与内存生命周期 |

多人联机、红石级逻辑、复杂合成系统、无限世界和 Vulkan 迁移暂放到第一版完成之后。每项都会引入较多独立系统，应按兴趣一次选择一条。

课程材料补齐后单独对照评分。体素世界可以承载图形学原理与交互展示，但不能未经确认就替代老师要求的机器人／贝塞尔等实验项目。

# 答辩知识卡（W3-5，口试准备 · 5 条）

> 每卡：核心问题 → 30 秒回答 → 展开（公式/实现位置）→ 常见追问。
> 代码位置按 `src/` 相对路径；回答时先给结论再给推导。

## 卡 1 · 为什么绕肩旋转要"平移—旋转—平移"？矩阵顺序错会怎样？

**30 秒：** 旋转矩阵只能绕原点转。手臂质心不在原点，直接乘 R 会把整条手臂甩飞（像螺旋桨）。所以用三明治 `T(p)·R·T(−p)`：先把关节支点 p 平移到原点，旋转，再平移回去——手臂就绕肩点了。级联时矩阵从右往左作用：`M = T·R·S` 是"先缩放、再旋转、后平移"，把 R 和 T 的顺序写反，得到的是绕世界原点公转而不是绕支点自转。

**展开：** 机器人每个部件的关节链是 `T(关节) · R(关节角) · T(杆件偏移)`（`src/robot.cpp`），行走时关节角是 1.6Hz 正弦：双腿相位相反（评分点"两条腿交换向前"）、双臂与同侧腿反相、重心每周期两次起伏。部件是世界场景图里的独立 Object，模型矩阵 `T(pos)·xform·S(size)`（`src/scene.cpp`、`src/renderer.cpp`）——这样经典管线、GLSL、阴影三条渲染路径自动一致。

**追问：** 为什么不用一个 Object 内部 glPushMatrix 画 9 个盒子？——GLSL 阴影的投影 uniform 是每个 Object 一次，单 Object 多部件会让 9 个盒子投影到同一位置（实际踩过并修复的坑）。

## 卡 2 · 六个视图和斜投影是怎么得到的？窗口拉变形怎么办？

**30 秒：** 每个视图 = 观察矩阵（把相机放到对应方位的 look-at）× 投影矩阵。三视图用正平行投影（直接取 [l,r]×[b,t]×[n,f] 长方体，无透视缩小），六个视图共用同一缩放系数保证尺度可比。斜投影在正投影上叠加 z 向错切，投影方向 `(L·cosα, L·sinα, −1)`：L=1 是斜等测（cavalier，沿轴向长度不缩），L=0.5 是斜二测（cabinet，更接近视觉习惯）。防变形的关键是透视投影的纵向视野按当前视口宽高比计算：窗口 1540×300 实测不变形。

**展开：** 投影矩阵构造在 `src/projection.cpp`；四视口用 `glViewport` 把窗口切四块（`src/app.cpp`），每块各自设置投影，透视视口保留完整森林、正交视口过滤外围树冠避免遮挡主体。正交前视/左视看到"地面是侧看平面、地平线以下是背景色"属正常现象。

**追问：** 正投影和透视投影本质区别？——透视除以 w（近大远小，视锥体），正投影不除（平行线仍平行，长方体视景体）。

## 卡 3 · 机器人沿贝塞尔曲线走，为什么不快不慢？

**30 秒：** 贝塞尔的参数 u 和弧长不是线性关系——曲线弯密的地方同样的 Δu 走的路程短，按 u 均匀推进会忽快忽慢。我的做法：每段曲线均匀采样 24 点累加出"参数→弧长"查找表，前进时按目标弧长 s 二分查表 + 线性插值求回位置和切向，`s = v·t` 前进，速度天然恒定。自检按 0.15 步长测位移，误差 < 0.005。

**展开：** N 个锚点生成 N 段三次贝塞尔闭曲线，控制点不手调，按 Catmull-Rom 公式自动生成：`C1 = P1 + (P2−P0)/6`、`C2 = P2 − (P3−P1)/6`，接缝切向连续（`src/bezier.cpp`）。求值用 de Casteljau 递推而不是展开的多项式——递推只有线性插值，数值稳定，避免大 `u` 小系数相乘的抵消误差。`B` 键可视化曲线/金色锚点/手柄；`P` 开关漫步。

**追问：** 为什么用闭曲线？——漫步是循环行为，闭曲线首尾相接且 Catmull-Rom 保证接缝 G1 连续，不需要处理端点掉头。

## 卡 4 · 树是模型文件做的吗？分形怎么实现、面数怎么控制？

**30 秒：** 不是文件，是运行时生成的。L-system 两步：字符串重写——如针叶文法 `F → F[/&F][//&F][///&F]F` 迭代 3 代；再用 3D 海龟解释字符串——F 前进长一段锥台枝干、`+−` 偏航、`&^` 俯仰、`/` 翻滚、`[ ]` 入栈出栈实现分叉，末端挂叶团。深度 `f` 键、分支角 `u/j` 键运行期可调即时重建。面数控制：分形段数随深度指数增长，粗选文法单树 4096 段、150 棵树会到百万三角形，改选每树 40~70 段的文法，全场景约 29 万三角形。

**展开：** 三种文法预设（针叶/阔叶/灌木），`/` 翻滚取确定性 ±120° 保证三枝轮生均分方位——曾因"先俯仰后翻滚"的顺序错误把树退化成一把梳子。同种子几何全等（自检比较完整顶点/法线/颜色数组，不只是数量），深度 +1 单调增长，两条断言保证可复现（`src/forest.cpp`）。

**追问：** 为什么深度只到 3~4？——段数 ≈ 分支因子^深度，指数增长；深度 +1 档位特意保留，现场演示"分形复杂度指数增长"。

## 卡 5 · GLSL 模式和经典固定管线差在哪？阴影怎么来的？

**30 秒：** 固定管线顶点级光照（Gouraud 插值，高光会闪烁缺失）；GLSL 把光照搬进片元着色器逐像素算：Blinn–Phong—— specular 用半角向量 `h = (l+v)/|l+v|`、`(n·h)^shininess`，比 Phong 反射角公式高光更稳定；再叠加天空/地面半球环境光、线性色彩运算、色调映射和逐像素距离雾。阴影是两遍渲染的 shadow map：第一遍以光源为视点把深度写进 2048² 纹理；第二遍每个像素变换到光源坐标系，与深度图比较，比深度图中最近的表面远就是被遮挡，3×3 PCF 多次采样软化边缘。F2 实时切换两种模式对比。

**展开：** 阴影通道复用同一套 VBO/EBO，几何只上传一次（`src/renderer.cpp`、`src/shaders.h`）。Blinn–Phong 半角向量等价于把"视线与光线夹角平分"，避免 Phong 在接近掠射角时镜面反射带畸形。固定管线模式仍保留，一是因为课程实验四至实验七基于兼容管线，二是做对比演示。

**追问：** 阴影为什么有锯齿/条纹（shadow acne）？怎么解决？——深度纹理分辨率有限导致自遮挡误判；用 bias 偏移 + PCF 多采样软化（本工程 2048² + 3×3 PCF）。
